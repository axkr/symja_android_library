# doc-json - the documentation pane's server answers, as static files

Generated by `matheclipse-web/tools/doc-export/export-docs.sh` (program: `DocExport.java`). Do not edit
by hand. Every file is the exact body the Java servlet sends (`{"content":"<html>"}` + CRLF, which is what the Undertow server writes), made
by running the servlet's own code, so `showPage(response)` in `doc.js` needs no change.

## Pages: replacing `GET /ajax/doc/<path>`

| the pane asks for        | fetch this file                  |
|--------------------------|----------------------------------|
| `loadDoc('/')`           | `index.json`                     |
| `loadDoc('/index')`      | `index.json`                     |
| `loadDoc('/05-lists')`   | `05-lists.json`                  |
| `loadDoc('/functions/Sin')` | `functions/Sin.json`          |

**One deliberate difference from the server:** `AJAXDocServlet` appends
`<script type="text/javascript">MathJax.Hub.Queue(['Typeset',MathJax.Hub,'mjax']); </script>` to every
page. The notebook uses KaTeX, where `MathJax` is undefined, so the export removes exactly that script
from the page files (`*.json` outside `search/`) and nothing else.

Rule: strip the leading `/`; the path `/` means `index`; append `.json`. 17 top-level pages
(`doc/*.md`) and 1418 function pages (`doc/functions/*.md`).

If the file does not exist (HTTP 404) show what the server shows for an unknown page:
`{"content":"<p>Insert a keyword and append a '*' to search for keywords. Example: <b>Int*</b>.</p>"}`
(also stored as `template.nothingFound` in `search-index.json`). The Markdown sources themselves link
to about 180 pages that do not exist (e.g. `functions/Grid`), so this case is real.

## Search: replacing `GET /ajax/doc/search/?query=q`

The servlet (`AJAXSearchServlet.findDocumentation`) does this for the query string `q`
(the pane has already stripped white space):

1. `matches` = every known name whose **lower-cased** spelling starts with `q.toLowerCase()`
   (`Documentation.getDocumentationByPrefix(q, false)`, a prefix match; `*` has no special meaning
   here, so `Int*` matches nothing). The result is in the order of `names` in `search-index.json`.
2. 2 or more matches: an answer that lists links to the matches that have a function page.
3. Exactly 1 match: the page text of that function (no "Main" back-link, unlike `functions/X.json`).
4. 0 matches and `q.length == 1`: the page text of the function called `q` (the C, D, E, I, N pages).
5. Otherwise the "nothing found" content.

### `search-index.json`

```json
{
  "version": 1,
  "names": ["Sin", "Cos", ...],      // all 3782 searchable names, canonical spelling, in match order
  "pageNames": ["Sin", ...],         // the subset that has a function page (functions/<name>.json)
  "singles": ["Sin", ...],           // names whose one-match answer is stored: search/<name>.json
  "oneCharFallbacks": [],            // one-character queries answered by search/<char>.json (rule 4)
  "template": { "listPrefix", "item", "separator", "listSuffix", "nothingFound" }
}
```

### How the browser reproduces the answer (JavaScript sketch)

```js
const lower = q.toLowerCase();
const matches = names.filter(n => n.toLowerCase().startsWith(lower));   // keep names' order
if (matches.length === 1) {
  // rule 3: a stored answer if the name has one, otherwise "nothing found"
  return singles.has(matches[0]) ? fetchJson('search/' + matches[0] + '.json') : nothing;
}
if (matches.length === 0) {
  return (q.length === 1 && oneCharFallbacks.has(q)) ? fetchJson('search/' + q + '.json') : nothing;
}
// rule 2: build the list. Only names with a page get an item; the separator follows every
// name except the LAST name of `matches` (even if that last one has no page).
let html = '', any = false;
matches.forEach((n, i) => {
  if (pageNames.has(n)) {
    html += template.item.replaceAll('{name}', n);
    any = true;
    if (i !== matches.length - 1) html += template.separator;
  }
});
content = any ? template.listPrefix + html.trimEnd() + template.listSuffix : template.nothingFound;
```

`trimEnd()` matters: when the last match has no page the text ends in `,` + space and the Markdown
renderer drops that space. Names are plain ASCII (letters, digits, `$`), so no escaping is needed in
`item`. Use `encodeURIComponent` for `$` in the fetch URL (`search/%24Assumptions.json`) if your
host does not accept it raw.

### Verified

`DocExport` checks, before it succeeds: for every prefix of every name (26610 prefixes) the rule in
step 1 gives the servlet's list in the servlet's order; for every prefix with 2+ matches (4481) the
list built from `template` is byte-identical to the servlet's answer; the stored one-match answers are
the servlet's output for that name.

## Notes

* `search/<name>.json` exists only for names no other name starts with (a one-match query can only
  hit such a name) that also have a page.
* Function-name case matters for file names (`functions/Sin.json`, not `sin.json`): links in the
  pages already use the canonical spelling.
